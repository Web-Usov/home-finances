## Как ссылаться на спецификацию

- Только по идентификатору правила (`OP-04`, `AC-06`), никогда по номеру строки или раздела.
- Определение правила — жирный маркер `**[ID]**` в начале пункта. Ссылка — просто `ID` в тексте задач, комментариев и тестов.

## Правила изменения спецификации

1. Идентификаторы стабильны: ID двузначные с ведущим нулём (`OP-04`), уникальны и **никогда не переиспользуются**.
2. Новое правило получает следующий свободный номер в своём префиксе (даже если по смыслу оно стоит в середине файла).
3. Отменённые правила не удаляются, а помечаются: `~~[XX-nn]~~ (отменено: причина)`; текст правила можно оставить зачёркнутым.
4. Смысл существующего правила меняется только осознанно; при существенном изменении лучше отменить правило и добавить новое.
5. Любые изменения в `docs/spec/**` требуют ревью человеком (CODEOWNERS).
6. Проверка согласованности: `node scripts/spec-check.mjs` (уникальность ID, существование ссылок, отчёт о покрытии тестами).
7. Язык спецификации — русский; тексты сообщений (`MSG`) приводятся дословно, как они показываются в интерфейсе.
