## Конкурентность

**Что нашли.** При ревью PR #22 (T-014, приёмочные тесты) воспроизведён дефект: `close` месяца, `PUT allocations` и `POST /envelopes` со стартовым остатком, отправленные одновременно с одной и той же `version`, в 1 из 40 раундов давали 200/200/201. Блокировку строки месяца `FOR UPDATE` брала только `OperationsService`, поэтому два писателя с одной версией могли оба пройти (нарушение DATA-12) и данные могли записаться в закрывающийся месяц (MON-03).

**Что исправлено (T-036, [PR #25](https://github.com/Web-Usov/home-finances/pull/25)).** Общий хелпер `apps/api/src/common/month-lock.ts`: каждая мутация, затрагивающая месяц, внутри своей транзакции блокирует строки месяцев и проверяет существование, `version` и статус под блокировкой.
- Единый порядок блокировок: целевой месяц и все последующие, по возрастанию периода, одним `ORDER BY period FOR UPDATE` (каскад увеличивает `version` у всех). Создание месяца: advisory-lock и все месяцы по порядку. Мутации «рабочего месяца»: определить, заблокировать, определить заново; если после блокировки рабочий месяц стал более ранним, то 409 `VERSION_CONFLICT`, а не блокировка не по порядку.
- MON-13 (не более одного повторно открытого месяца) проверяется под блокировкой.
- Заодно исправлено: параллельное создание конвертов с одним именем и параллельное создание одного месяца давали уникальное нарушение Prisma, то есть 500; теперь 409 `ENVELOPE_NAME_DUPLICATE` и 422/409.

**Тесты гонок** (реальная параллельность через `t.listen()`, 15 раундов × 14 гонок): `month-lock.concurrency.close-vs-mutation.int-spec.ts` (close против allocations, дохода, списания, правки/удаления операции, создания конверта с остатком, архивации, следующего месяца), `month-lock.concurrency.same-kind.int-spec.ts` (пары одинаковых мутаций, пара reopen для MON-13, конверты с одним именем с месяцем и без, создание первого месяца), `month-lock.spec.ts`. На прежних сервисах 7 из 8 гонок `close vs ...` падали уже в первых раундах (200/200). Эти наборы в зелёном `pnpm verify`.

**Остаётся.** T-028 (ограничение на уровне БД для MON-13) полезно как защита в глубину. Раунды сокращены с 20 до 15, чтобы наборы укладывались в ~45 с на загруженной машине.

## Демо-сценарий (проверено вживую)

Условия: собранный API (`apps/api`, `node dist/main.js`, порт 3217) на **тестовой БД** `family_budget_test`, отдельная
схема `demo_e01` (создана `prisma migrate deploy`, после прогона удалена); dev-БД `family_budget` не использовалась.
Суммы в запросах в рублях строкой, в ответах в копейках. Для повторения в Swagger UI (`/api`) выполняйте те же вызовы;
`version` берите из `GET /api/v1/months`.

Сценарий прогнан заново на актуальной сборке `master` (шаги 5 дополнены превью и `period`); реальные ответы (идентификаторы сокращены в тексте, значения подлинные):

**1. Месяцы (MON-05, MON-06, MON-07)**

- `POST /months {"period":"2026-11","income":"100000"}` → 201, `status: open`, `incomeMinor: 10000000`, `version: 2` (после T-032 новый месяц пересчитывается при создании; раньше было 1).
- `POST /months {"period":"2026-12"}` → 201, `status: draft`, `incomeMinor: 0`, `version: 2`.
- `POST /months {"period":"2027-02"}` (пропуск месяца) → 422 `INVALID_PERIOD`.
- Конверты: `POST /envelopes {"name":"Еда","initialBalance":"10000"}` → `balanceMinor: 1000000`; `{"name":"Резерв"}` → `0`.

**2. Смена дохода**

`PATCH /months/2026-11 {"income":"120000","version":3}` → 200, `incomeMinor: 12000000`, `freeFundsMinor: 12000000`, `version: 4`.

**3. Списание сверх остатка (AC-06)**

`POST /operations {"type":"expense","sourceEnvelopeId":<Еда>,"amount":"15000","version":4}` → 201:
`requestedMinor: 1500000`, `coveredMinor: 1000000`, `uncoveredMinor: 500000`, `sourceBalanceAfter: 0`, `sequenceNo: 2`.
Списание сохранено полностью, не покрыто 5 000 ₽. Затем списание 500 ₽ → `sequenceNo: 3`, `uncoveredMinor: 50000`.

**4. Перевод, порядок, удаление (AC-07, AC-12, AC-13)**

- Перевод 50 000 ₽ из пустого «Резерва» → 409 `TRANSFER_EXCEEDS_BALANCE`, «Доступно 0.00 ₽. Перевести только 0.00 ₽?».
- `PATCH /operations/<№2> {"amount":"12000","version":6}` → 200, `sequenceNo` по-прежнему 2, `uncoveredMinor: 200000`, `version: 7`.
- `DELETE /operations/<№3>?version=7` → 200, `version: 8` (месяц пересчитан).
- `GET /operations` → операции `1 initial_balance` и `2 expense` (12 000 ₽, не покрыто 2 000 ₽); №3 удалена, порядок сохранён.

**5. Закрытие и повторное открытие (AC-14, AC-15, AC-17)**

- `POST /months/2026-11/close {"version":8}` → 200: `2026-11` — `closed`, черновик `2026-12` стал `open`.
- `PATCH /months/2026-11 {"income":"130000","version":9}` → 409 `MONTH_LOCKED`, «Месяц закрыт. Откройте его повторно…».
- `PATCH /operations/<№2>` в закрытом месяце → 409 `MONTH_LOCKED`.
- `GET /months/2026-11/reopen-preview` (API-20, MON-12) → 200, закрытый месяц и `recalcRange: {"from":"2026-11","to":"2026-12"}`; ничего не меняет и `version` не требует. `POST /operations` с `"period":"2026-11"` в закрытый месяц → 409 `MONTH_LOCKED`.
- `POST /months/2026-11/reopen {"version":9}` → 200: `status: reopened`, `recalcRange: {"from":"2026-11","to":"2026-12"}`; версия месяца 10; диапазон тот же, что показало превью.
- **Операция в повторно открытый месяц (API-21, SCOPE-33)** при открытом рабочем 2026-12: `POST /operations {"type":"expense","sourceEnvelopeId":<Еда>,"amount":"300","comment":"Поправка за ноябрь","period":"2026-11","version":10}` → 201: `sequenceNo: 3`, `uncoveredMinor: 30000`, `summary.period: 2026-11`, `status: reopened`, `version: 11`. В `GET /months` версии обоих месяцев 11 (каскад дошёл до 2026-12).
- Формат ответов мутаций единый: `PATCH /months/...` и операции возвращают `data.summary` (API-22).

**6. Приёмка по тестам**: `pnpm verify` зелёный (см. выше), AC-05…AC-17 покрыты.

## Известные ограничения и риски

- **Расширение эпика принято**: PR #12 смёржен, решения в спеке (API-20…API-22, ENV-14, MSG-07, MON-16, UI-16); T-024, T-025, T-027, T-031 выполнены и включены в отчёт.
- **Оставшийся пробел**: T-028 (ограничение БД для MON-13) не сделана, MON-13 защищена только блокировками (T-036).
- **Превью-endpoint консультативный**: между превью и reopen состояние может измениться; `reopen` перепроверяет под блокировкой.
- **`PeriodSchema` проверяет только форму `YYYY-MM`**: `period: "2026-13"` даёт 404 `MONTH_NOT_FOUND`, а не 422 (замечание T-025).
- **Коды ошибок вне спеки**: `INVALID_PERIOD` (пропуск месяца), `INVALID_STATUS_TRANSITION` (закрытие черновика, второй `reopened`), `OPERATION_NOT_FOUND`; в API-18 не перечислены.
- **Правка перевода (HIST-09)**: «доступный остаток» берётся по позиции операции; последующие операции, потеряв покрытие, становятся непокрытыми, а не блокируют правку (решение T-005).
- **Начальный остаток** (OP-10) нельзя править и удалять через API операций (422).
- **Путь `/v1`**: спека API-11 не упоминает `/v1` и параметр `version` у `DELETE` (передаётся в query).
- **Версия нового месяца**: после T-032 месяц при создании отдаёт `version: 2`, а не 1 (пересчёт при создании, ADR 0005); клиенты должны брать `version` из ответа, а не предполагать 1.
- **Скриншотов e2e нет**: эпик без UI, `e2e:full` содержит только смоук приложения.
