## Итог

Все шесть задач эпика (T-003, T-004, T-005, T-006, T-032, T-034) смёржены в `master`, `pnpm verify` и `pnpm e2e:full` зелёные.
Через API работают: смена дохода с каскадным пересчётом, создание/правка/удаление операций со стабильным порядком,
история, закрытие и повторное открытие месяца, автопереход черновика в открытый, защита закрытых месяцев (`MONTH_LOCKED`)

локального API на тестовой БД (вывод ниже). Все 50 правил эпика теперь имеют ссылки из тестов. Часть формулировок спеки неоднозначна, это зафиксировано в разделе «Ограничения».

## Демо-сценарий (проверено вживую)

Условия: собранный API (`apps/api`, `node dist/main.js`, порт 3217) на **тестовой БД** `family_budget_test`, отдельная
схема `demo_e01` (создана `prisma migrate deploy`, после прогона удалена); dev-БД `family_budget` не использовалась.
Суммы в запросах в рублях строкой, в ответах в копейках. Для повторения в Swagger UI (`/api`) выполняйте те же вызовы;
`version` берите из `GET /api/v1/months`.

Сценарий прогнан повторно на сборке после T-032 (см. изменение ниже); реальные ответы (идентификаторы сокращены в тексте, значения подлинные):

**1. Месяцы (MON-05, MON-06, MON-07)**

- `POST /months {"period":"2026-11","income":"100000"}` → 201, `status: open`, `incomeMinor: 10000000`, `version: 2` (после T-032 новый месяц пересчитывается при создании; раньше было 1).
- `POST /months {"period":"2026-12"}` → 201, `status: draft`, `incomeMinor: 0`, `version: 2`.
- `POST /months {"period":"2027-02"}` (пропуск месяца) → 422 `INVALID_PERIOD`.
- Конверты: `POST /envelopes {"name":"Еда","initialBalance":"10000"}` → `balanceMinor: 1000000`; `{"name":"Резерв"}` → `0`.

**2. Смена дохода**

`PATCH /months/2026-11 {"income":"120000","version":3}` → 200, `incomeMinor: 12000000`, `freeFundsMinor: 12000000`, `version: 4`.

**3. Списание сверх остатка (AC-06)**

`POST /operations {"type":"expense","sourceEnvelopeId":<Еда>,"amount":"15000","version":4}` → 201:
`requestedMinor: 1500000`, `coveredMinor: 1000000`, `uncoveredMinor: 500000`, `sourceBalanceAfter: 0`, `sequenceNo: 2`.
Списание сохранено полностью, не покрыто 5 000 ₽. Затем списание 500 ₽ → `sequenceNo: 3`, `uncoveredMinor: 50000`.

**4. Перевод, порядок, удаление (AC-07, AC-12, AC-13)**

- Перевод 50 000 ₽ из пустого «Резерва» → 409 `TRANSFER_EXCEEDS_BALANCE`, «Доступно 0.00 ₽. Перевести только 0.00 ₽?».
- `PATCH /operations/<№2> {"amount":"12000","version":6}` → 200, `sequenceNo` по-прежнему 2, `uncoveredMinor: 200000`, `version: 7`.
- `DELETE /operations/<№3>?version=7` → 200, `version: 8` (месяц пересчитан).
- `GET /operations` → операции `1 initial_balance` и `2 expense` (12 000 ₽, не покрыто 2 000 ₽); №3 удалена, порядок сохранён.

**5. Закрытие и повторное открытие (AC-14, AC-15, AC-17)**

- `POST /months/2026-11/close {"version":8}` → 200: `2026-11` — `closed`, черновик `2026-12` стал `open`.
- `PATCH /months/2026-11 {"income":"130000","version":9}` → 409 `MONTH_LOCKED`, «Месяц закрыт. Откройте его повторно…».
- `PATCH /operations/<№2>` в закрытом месяце → 409 `MONTH_LOCKED`.
- `POST /months/2026-11/reopen {"version":9}` → 200: `status: reopened`, `recalcRange: {"from":"2026-11","to":"2026-12"}`; в `GET /months` версии обоих месяцев выросли до 10.

**6. Приёмка по тестам**: `pnpm verify` зелёный (см. выше), AC-05…AC-17 покрыты.

## Известные ограничения и риски

- **Расширение эпика (ожидает решения по [PR #12](https://github.com/Web-Usov/home-finances/pull/12))**: предложены новые задачи T-024 (превью повторного открытия),
  T-025 (необязательный `period` в `POST /operations`), T-027 (единая форма сводки в ответах), T-031 (интеграционный тест «непокрытые операции не блокируют закрытие»).
  Они не на `master`, в отчёт как выполненные не входят. Пока PR #12 открыт, по ним можно принять решение: включать в E-01 или нет.
- **Операции только в «рабочем» месяце**: `POST /operations` не принимает `period`; пока есть открытый месяц, нельзя вносить операции в повторно открытый (T-025). Влияет на экран операций (T-011).
- **Форма ответов мутаций неоднородна**: у разных эндпоинтов сводка имеет разные поля (без баланса конвертов); API-16 неоднозначен (T-027).
- **MON-12 (предупреждение до повторного открытия)** на API не реализуемо без превью-эндпоинта (T-024): диапазон возвращается только после действия.
- **Коды ошибок вне спеки**: `INVALID_PERIOD` (пропуск месяца), `INVALID_STATUS_TRANSITION` (закрытие черновика, второй `reopened`), `OPERATION_NOT_FOUND`; в API-18 не перечислены.
- **Правка перевода (HIST-09)**: «доступный остаток» берётся по позиции операции; последующие операции, потеряв покрытие, становятся непокрытыми, а не блокируют правку (решение T-005).
- **Начальный остаток** (OP-10) нельзя править и удалять через API операций (422).
- **Путь `/v1`**: спека API-11 не упоминает `/v1` и параметр `version` у `DELETE` (передаётся в query).
- **Версия нового месяца**: после T-032 месяц при создании отдаёт `version: 2`, а не 1 (пересчёт при создании, ADR 0005); клиенты должны брать `version` из ответа, а не предполагать 1.
- **Скриншотов e2e нет**: эпик без UI, `e2e:full` содержит только смоук приложения.
