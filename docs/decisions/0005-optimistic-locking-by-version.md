# 0005. Оптимистичная блокировка через поле version

## Статус

Принято (2026-08-03, реализовано с 2026-08-17). Действует.

## Контекст

Приложение может быть открыто в двух вкладках; без контроля версий одна вкладка молча перезапишет данные другой (DATA-12). Пользователь один, поэтому пессимистичные блокировки избыточны.

## Решение

- `BudgetMonth.version` (`Int`, по умолчанию 1) — счётчик версии месяца.
- Мутирующие запросы, зависящие от состояния месяца, передают ожидаемый `version`; несовпадение даёт 409 `VERSION_CONFLICT` (API-17, API-18). Пример: сохранение распределения (`PUT /months/:period/allocations`).
- Каждый каскадный пересчёт увеличивает `version` у всех затронутых месяцев (период ≥ изменённого).
- Порядок проверок: сначала версия, затем статус месяца — устаревшая вкладка получает `VERSION_CONFLICT`, даже если месяц успел закрыться.

## Последствия

- Клиент обязан читать актуальный `version` и передавать его в мутации; при 409 — перечитать данные.
- Новые мутирующие эндпоинты, зависящие от состояния месяца, следуют тому же правилу.

## Дополнение (2026-11-01): заголовки `If-Match` / `ETag`

Решение человека по PR #33: способ передачи версии единый для всех изменяющих запросов, привязанных к месяцу (спецификация: API-25, API-26, API-27).

- Клиент передаёт ожидаемую версию месяца в заголовке `If-Match: "<version>"` (строковая форма ETag) в `PATCH`/`PUT`/`POST`/`DELETE`. Поле `version` в теле запросов и query-параметр `?version=` отменяются.
- Ответы чтения и мутаций месяца возвращают текущую версию в заголовке `ETag: "<version>"`; поле `version` в теле остаётся для отображения.
- Нет `If-Match` — 428 `PRECONDITION_REQUIRED`; версия устарела — 409 `VERSION_CONFLICT` (сохранён доменный код вместо 412 Precondition Failed). Порядок проверок прежний: существование → версия → статус → бизнес-правила.
- CORS: сервер отдаёт `Access-Control-Expose-Headers: ETag` и разрешает `If-Match`.
- Остальное (счётчик `BudgetMonth.version`, рост версии у всех затронутых месяцев каскадом, перечитывание при 409) без изменений. Реализация — задача T-050.
