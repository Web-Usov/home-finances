# 0005. Оптимистичная блокировка через поле version

## Статус

Принято (2026-08-03, реализовано с 2026-08-17). Действует.

## Контекст

Приложение может быть открыто в двух вкладках; без контроля версий одна вкладка молча перезапишет данные другой (DATA-12). Пользователь один, поэтому пессимистичные блокировки избыточны.

## Решение

- `BudgetMonth.version` (`Int`, по умолчанию 1) — счётчик версии месяца.
- Мутирующие запросы, зависящие от состояния месяца, передают ожидаемый `version`; несовпадение даёт 409 `VERSION_CONFLICT` (API-17, API-18). Пример: сохранение распределения (`PUT /months/:period/allocations`).
- Каждый каскадный пересчёт увеличивает `version` у всех затронутых месяцев (период ≥ изменённого).
- Порядок проверок: сначала версия, затем статус месяца — устаревшая вкладка получает `VERSION_CONFLICT`, даже если месяц успел закрыться.

## Последствия

- Клиент обязан читать актуальный `version` и передавать его в мутации; при 409 — перечитать данные.
- Новые мутирующие эндпоинты, зависящие от состояния месяца, следуют тому же правилу.
