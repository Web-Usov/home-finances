# 0009. Процесс: PR через gh, CI как шлюз, агент-ревьюер, приёмка человеком на вехах

## Статус

Принято (2026-10-28). Действует.

## Контекст

Нужно, чтобы агент в свежей сессии мог взять готовую задачу, реализовать её, доказать корректность и доставить через PR, а человек не ревьюил каждую мелочь. До этого CI не срабатывал (триггеры только на main/develop при дефолтной ветке master), а проверки были разрозненными.

## Решение

- Доставка: GitHub PR через `gh`; слияние `gh pr merge --squash --auto`; прямые пуши в master запрещаются защитой ветки.
- Шлюз: CI с обязательными проверками `verify`, `contract`, `e2e`; локально то же гарантирует `pnpm verify`.
- Каждый PR проверяет агент-ревьюер.
- Человек принимает работу на вехах (эпиках), а не по каждому PR. Исключение: PR, затрагивающие `docs/spec/**` и `docs/decisions/**`, требуют ревью человека (CODEOWNERS → @Web-Usov).
- Одна задача = одна сессия = одна ветка/worktree; сессия не завершается с незакоммиченными изменениями.
- Изменения спецификации — только через роль planner и ревью человека.
- Пуш в origin и настройка branch protection заранее одобрены владельцем.

## Последствия

- Качество гарантируется автоматикой, а не вниманием человека; слабые места проверок закрываются в CI, а не в ревью.
- Спецификация и ADR защищены от «тихих» правок агентами.

## Дополнение (2026-10-29): детали реализации процесса

- **Ревью без аппрува.** Автор PR и агент-ревьюер используют один GitHub-аккаунт, а GitHub не позволяет одобрить собственный PR. Поэтому вердикт ревьюера (`LGTM` / `CHANGES REQUESTED`) публикуется комментарием `gh pr review --comment`, а branch protection не требует approving review для агентских PR; жёсткий шлюз — обязательные проверки CI. При `CHANGES REQUESTED` авто-слияние отключается (`gh pr merge --disable-auto`). Между окончанием CI и вердиктом возможна гонка; для рискованных изменений оркестратор откладывает включение авто-слияния (`/ship hold`).
- **Статус `done`.** Коммит в `master` после слияния запрещён защитой ветки, поэтому последний коммит самого PR ставит `status: done` и `pr: <url>` (URL известен после `gh pr create`), затем включается авто-слияние. `tasks check --gh` предупреждает, если задача `done`, а PR не смёржен.
- **Права агентов** описаны в `.opencode/agents/*.md`: implementer не правит `docs/spec/**`, `docs/decisions/**`, `epics/**`; force-push запрещён; слияние только `gh pr merge --squash --auto`. Planner не сливает PR сам: PR со спецификацией/ADR/эпиками сливает человек. Права на shell — сопоставление по шаблонам, а не песочница.
- **Защита ветки на практике.** Число обязательных approving-ревью = 0: агенты и владелец работают под одним GitHub-аккаунтом `Web-Usov`, самоодобрение невозможно, поэтому CODEOWNERS носит лишь рекомендательный характер. Ревью человеком для `docs/spec/**`, `docs/decisions/**`, `epics/**` обеспечивается процессом: такие PR не получают авто-слияние (`/ship hold`), их сливает человек. Обязательные проверки остаются `verify`, `contract`, `e2e`.
