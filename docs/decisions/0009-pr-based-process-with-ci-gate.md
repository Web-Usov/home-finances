# 0009. Процесс: PR через gh, CI как шлюз, агент-ревьюер, приёмка человеком на вехах

## Статус

Принято (2026-10-28). Действует; механизмы вводятся поэтапно (quality gate, task system, agent config).

## Контекст

Нужно, чтобы агент в свежей сессии мог взять готовую задачу, реализовать её, доказать корректность и доставить через PR, а человек не ревьюил каждую мелочь. До этого CI не срабатывал (триггеры только на main/develop при дефолтной ветке master), а проверки были разрозненными.

## Решение

- Доставка: GitHub PR через `gh`; слияние `gh pr merge --squash --auto`; прямые пуши в master запрещаются защитой ветки.
- Шлюз: CI с обязательными проверками `verify`, `contract`, `e2e`; локально то же гарантирует `pnpm verify`.
- Каждый PR проверяет агент-ревьюер.
- Человек принимает работу на вехах (эпиках), а не по каждому PR. Исключение: PR, затрагивающие `docs/spec/**` и `docs/decisions/**`, требуют ревью человека (CODEOWNERS → @Web-Usov).
- Одна задача = одна сессия = одна ветка/worktree; сессия не завершается с незакоммиченными изменениями.
- Изменения спецификации — только через роль planner и ревью человека.
- Пуш в origin и настройка branch protection заранее одобрены владельцем.

## Последствия

- Качество гарантируется автоматикой, а не вниманием человека; слабые места проверок закрываются в CI, а не в ревью.
- Спецификация и ADR защищены от «тихих» правок агентами.
