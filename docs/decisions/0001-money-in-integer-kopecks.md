# 0001. Деньги хранятся в целых копейках

## Статус

Принято (2026-08-03). Действует.

## Контекст

Приложение ведёт семейный бюджет с точностью до 0,01 ₽, а результаты сравниваются с точностью до копейки (DOD-01, AC-01…AC-22). Арифметика с float накапливает ошибки округления, а каскадный пересчёт по десяткам месяцев их усиливает. Спецификация прямо запрещает float (FIN-08, FIN-09).

## Решение

- В базе (Prisma) и во всём коде суммы — целое число копеек (`Int`, `number` в TS; поля именуются `*Minor` / `*_minor`).
- В API суммы передаются десятичной строкой вида `"15000.00"` (API-14).
- Единственные точки конвертации — `parseMoneyMinor` и `formatMoneyMinor` из `@family-budget/types`.
- Любая арифметика с float для денег запрещена (в том числе промежуточная).

## Последствия

- Расчёты детерминированы и воспроизводимы, тесты сравнивают числа точно.
- Максимум `Int` PostgreSQL (≈ 21,4 млн ₽ на значение) достаточен для целевых объёмов MVP; при росте потребуется `BigInt` (отдельное решение).
- Любой новый код с деньгами обязан пользоваться хелперами, а не ручным парсингом.
