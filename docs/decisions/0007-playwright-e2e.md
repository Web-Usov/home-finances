# 0007. E2E-тесты на Playwright

## Статус

Принято (2026-10-28). Заменяет прежнее решение «E2E вне охвата» (owner decision 2026-10-28).

## Контекст

В плане `domain-modules-impl` браузерные E2E-тесты были сознательно исключены («Not included: E2E browser tests (out of scope per user choice)», `docs/archive/omo/drafts/domain-modules-impl.md`). Спецификация, однако, требует E2E-проверки сценариев первого запуска, обычного месяца, черновика, закрытия и исправления прошлого (NFR-27), а критерии приёмки AC-* автоматизируются (DOD-02). Для процесса «агент реализует — CI доказывает» нужна проверка приложения целиком.

## Решение

- Владелец разрешил Playwright E2E.
- Workspace `e2e/` поднимает API на тестовой БД и Expo web.
- `e2e:smoke` запускается в CI на каждом PR; `e2e:full` — на master и перед вехами (приёмкой эпиков).
- При падении сохраняются скриншоты и trace.

## Последствия

- Прежнее исключение E2E отменено; архивные планы остаются как история.
- CI дольше и требует браузеров; сценарии должны быть детерминированными и изолированными по БД.
- Покрытие AC-* ссылками на ID (`scripts/spec-check.mjs`) учитывает E2E-файлы.
