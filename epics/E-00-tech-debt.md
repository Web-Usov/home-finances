# E-00. Технический долг и соответствие спеке

## Ценность для пользователя

Прямой пользовательской ценности нет: эпик убирает расхождения кода со спецификацией, чтобы последующие фичи строились на предсказуемой основе (корректные коды ошибок, ссылки на правила вместо номеров строк).

## Ключевые фичи

- Ошибки валидации запросов возвращаются с кодом 422 по контракту API.
- Единый механизм валидации (Zod), без остатков class-validator.
- Все комментарии в коде ссылаются на правила спеки по ID, а не по номерам строк.

## Охват правил спеки

- `API-17` — ошибки валидации возвращают 422.
- `NFR-02` — API на NestJS, модульная доменная логика.
- `NFR-18` — проверка блокировки на стороне сервера (сквозное требование для всех задач).

## Критерии приёмки вехи

Владелец проверяет:

1. Запрос с заведомо неверным телом (например, `POST /api/v1/envelopes` с пустым названием) возвращает HTTP 422 — демонстрируется в Swagger UI.
2. Поиск `SPECIFICATION.md line` / `spec line` по `apps/` и `packages/types/src` ничего не находит.
3. CI (`pnpm verify`) зелёный.

## Вне охвата

- Новые пользовательские функции.
- Любые изменения самой спецификации.
